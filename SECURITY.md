# Security Policy

## Supported Versions

Security fixes target the current `main` branch until the project starts
publishing versioned releases.

## Reporting a Vulnerability

Please do not open a public issue for suspected vulnerabilities. Report them
privately through GitHub private vulnerability reporting when it is enabled for
the repository, or contact the repository owner directly.

Include:

- affected commit or version
- reproduction steps
- expected impact
- any logs or MCP responses with secrets and proprietary data removed

## Sensitive Data

Debugging embedded targets can expose private firmware details. Never include
credentials, signing keys, customer data, full memory dumps, proprietary source
snippets, or private hardware identifiers in public reports.
